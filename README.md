Практическая работа №3 по компьютерным сетям: **сеть из нескольких маршрутизаторов, поиск кратчайшего пути и шифрование сообщений**. Работа продолжает проект практической работы №2.

Клиенты из разных сетей обмениваются сообщениями через цепочку маршрутизаторов. Каждый маршрутизатор сам выбирает следующий узел по алгоритму Дейкстры, а текст сообщений шифруется на стороне клиентов и маршрутизаторам не виден.

## Что реализовано

- Несколько маршрутизаторов (4) и клиенты по TCP и UDP.
- Топология сети и стоимости связей в `network.json`.
- Поиск кратчайшего пути по алгоритму Дейкстры (без сторонних библиотек).
- Таблица маршрутизации при запуске каждого маршрутизатора.
- Шифрование сообщений методом XOR с ключом, данные передаются в HEX.
- Собственный протокол прикладного уровня SRP.
- Приоритет сообщений `NORMAL` и `HIGH`.
- Проводной и беспроводной типы каналов.

## Схема сети

```
Client1 (TCP)        Client2 (TCP)
     │                    │
  Router1 ──── 2 ──── Router2
     │                    │
     5                    3
     │                    │
     └────── Router3 ─────┘ ──── Client3 (UDP)
                │
                2 (WIRELESS)
                │
         WirelessRouter ──── Client4 (UDP)
```

Стоимость связей: Router1–Router2 = 2, Router1–Router3 = 5, Router2–Router3 = 3, Router3–WirelessRouter = 2 (беспроводной канал).

У каждого маршрутизатора свои порты, потому что один порт нельзя занять дважды. Клиенты подключаются к порту своего маршрутизатора, а маршрутизаторы передают пакеты друг другу по TCP-порту следующего узла.

## Протокол SRP

Формат пакета данных:

```
SRP|DATA|SOURCE|TARGET|PROTOCOL|PRIORITY|ENCRYPTED|PAYLOAD
```

| Поле      | Значение                                      |
|-----------|-----------------------------------------------|
| SRP       | название протокола                            |
| DATA      | тип пакета                                    |
| SOURCE    | отправитель                                   |
| TARGET    | получатель                                    |
| PROTOCOL  | протокол отправителя (TCP или UDP)            |
| PRIORITY  | NORMAL или HIGH                               |
| ENCRYPTED | 1, если payload зашифрован                    |
| PAYLOAD   | зашифрованный текст в HEX                     |

Регистрация клиента: `SRP|REGISTER|ИмяКлиента`.

## Как это работает

1. Клиент вводит ключ, шифрует текст через XOR и отправляет пакет своему маршрутизатору.
2. Маршрутизатор определяет, к какому маршрутизатору подключён получатель (`clients.json`).
3. Если получатель подключён к этому же маршрутизатору, пакет доставляется клиенту по его протоколу (TCP или UDP).
4. Иначе по алгоритму Дейкстры строится кратчайший путь, определяется следующий маршрутизатор (`path[1]`) и пакет передаётся ему.
5. Каждый маршрутизатор на пути выводит путь, стоимость и тип канала. Топология `network.json` перечитывается при каждом пакете, поэтому изменение стоимости действует без перезапуска.
6. Получатель расшифровывает сообщение своим ключом. При неверном ключе текст остаётся нечитаемым.

## Запуск

Нужен Python 3. Сторонние библиотеки не требуются. Запускать из папки проекта.

1. Маршрутизаторы, каждый в своём терминале:
   ```
   py router.py Router1
   py router.py Router2
   py router.py Router3
   py router.py WirelessRouter
   ```
2. Клиенты, каждый в своём терминале. В файле клиента перед запуском поменять `NAME`:
   ```
   py client_tcp.py    # NAME = "Client1" (для Client2 использовать копию с NAME = "Client2")
   py client_udp.py    # NAME = "Client3" (для Client4 использовать копию с NAME = "Client4")
   ```
3. Каждый клиент запрашивает ключ шифрования. Для общения клиенты должны использовать один и тот же ключ.
4. Ввести получателя, приоритет (`NORMAL` или `HIGH`) и сообщение. Для выхода ввести `exit`.

## Проверяемые сценарии

| Сценарий                          | Что проверяется                                          |
|-----------------------------------|----------------------------------------------------------|
| Client1 → Client2                 | TCP → TCP через Router1 и Router2                        |
| Client1 → Client3                 | TCP → UDP                                                |
| Client1 → Client4                 | путь `Router1 -> Router3 -> WirelessRouter`, стоимость 7 |
| Client с другим ключом            | расшифровка с неверным ключом                            |
| Router1–Router3 = 10 в network.json | изменение маршрута: через Router2                      |
| Удалена связь Router1–Router3     | маршрут через Router2                                    |
